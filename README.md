# 肿瘤登记增量同步

> 肿瘤登记员每周把科室上报到齐的登记表打开，点一次「与院内数据对齐」：插件按登记主索引批量检索院内权威记录，逐字段标出差异与建议值；登记员在「确认」列人工确认后，**只把变化的字段**写回原表新列并推给专病库登记接口，表尾留下推送回执，院内命中但本表缺行的漏登记行在同一张表里看得见。

本产品是**表格内插件 + 本机引擎**两件套：Excel 加载宏、WPS JSA 宏、CSV 直跑三个入口共用同一份 JSON 契约，所有业务逻辑（检索、比对、确认闸门、幂等推送）都在本机 Node/TS 引擎里，宏只做「取行 → 调引擎 → 回读结果写回」。不开端口、不装数据库、不改写登记员手工填的列。

---

## 适用场景 / 目标岗位

| 岗位 | 什么时候用 | 得到什么 |
|------|------------|----------|
| 肿瘤登记员 | 每周科室随访登记表上报到齐后，点一次「与院内数据对齐」（单次 100–300 行） | 原表末尾多出五列：院内值、差异、建议值、确认、AI 说明；不一致的字段被标红并给出建议值 |
| 肿瘤登记员 | 在「确认」列把要采纳的行改成「采纳」后再跑一次推送 | 只有变化字段被推给专病库；表尾回执区给出已推送 / 待确认 / 失败计数与批次键 |
| 登记处负责人 | 周会前想知道本周期推了多少、还悬着多少 | 表尾回执区的批次键、计数与检索参数串，不用翻原始记录 |
| 质控科 | 抽查登记质量、看有没有漏登记 | 表尾「院内命中但本表缺行」区块列出院内有、本表无的登记号 |
| 信息科 | 给登记员装好本机环境、排查跑失败的行 | 引擎输出逐行问题清单（行号、错误码、处置建议），401/403 直接点名缺哪个环境变量 |

## 能力要点

- **一次点按钮，批量检索院内记录**：按登记主索引批量查院内权威记录，不再一患者一次手工检索（100–300 行一批）。
- **只标真正变了的地方**：逐字段算出最小差异集合（新增 / 修改 / 删除），值没变的字段一个字都不动，不做整表粘贴覆盖。
- **人工确认是唯一闸门**：差异行的「确认」列默认「待确认」，只有登记员改成「采纳」的行才会被推送；未确认行连请求体都不构造。
- **写前先比对，冲突不硬写**：推送前用检索时的院内快照比对当前值，院内已被人改过的行拒写并标「院内已变更，需重查」，同批其余行照常推。
- **同一份改动不会被推两遍**：每次推送按内容算幂等键，重跑、断点续跑都只写一条登记条目。
- **漏登记的行同表可见**：院内有、本表没有的登记号追加到表尾缺行区，确认列留「待确认」，等登记员自己决定要不要补录。
- **脏行不丢、改法写清楚**：读表阶段发现的列数不符 / 缺登记号 / 登记号重复，与检索阶段发现的院内命中多条 / 院内无此记录 / 响应不是 JSON，统一归成一张待人工处理清单：哪一行、什么问题、为什么、该怎么改，一条一行；清单落盘前自动脱敏，不含患者明报。

## 快速开始

### 依赖

- Node.js ≥ 20（本机引擎运行时）
- Excel（加载宏 `.bas`）或 WPS 表格（JSA 宏 `.js`）之一 —— 没有也能用 CSV 直跑入口
- 院内可达的两个端点：院内 FHIR 服务（只读）与专病库登记接口（写入）

### 安装

```bash
# 在项目目录内
npm install          # 安装依赖（运行时依赖只有 zod）
npm run build        # 编译到 dist/
```

### 配置

凭据只从环境变量读，**不写进代码、不提交进仓库**。复制样例后按院内实际情况填写：

```bash
cp .env.example .env
# 编辑 .env，填入院内端点与令牌
```

```bash
# 把配置载入当前 shell（Windows PowerShell 用 $env:VAR="value" 逐条设置）
export CDR_BASE_URL="https://cdr.example-hospital.internal"
export CDR_API_TOKEN="<院内令牌>"
export CDR_IDENTIFIER_SYSTEM="urn:oid:2.16.156.10011.0.1"
export REGISTRY_BASE_URL="https://registry.example-hospital.internal"
export REGISTRY_API_TOKEN="<专病库令牌>"
```

配置齐备与否随时可体检：

```bash
node dist/cli.js doctor
```

### 构建与验证

```bash
npm run build          # 编译
npm run typecheck      # 类型检查（strict）
npm test               # 运行测试
node dist/cli.js doctor   # 配置体检，缺哪个变量会逐个点名
```

### 主命令速查

```bash
node dist/cli.js doctor                              # 体检环境变量与配置
node dist/cli.js sheet --in samples/registry-sample.csv   # 读表：打印规范化行与行级问题清单
node dist/cli.js sheet --in 登记表.csv --checklist 待人工处理清单.csv   # 读表 + 导出待人工处理清单
node dist/cli.js caliber --in 登记表.csv               # 口径自查：哪些列参与比对、派生字段按哪条口径算
node dist/cli.js align --in rows.json --out result.json   # 对齐：检索 → 比对 → 出结果表
node dist/cli.js push  --in result.json --out push.json    # 推送：按确认列筛选后推专病库
node dist/cli.js summary --in result.json                 # 摘要：本周期推了多少、还悬多少
```

## 命令 / API / 配置说明

### 关键配置项

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `CDR_BASE_URL` | 必填，无默认 | 院内 FHIR 服务基地址；检索路径为 `{CDR_BASE_URL}/fhir/R4/...` |
| `CDR_API_TOKEN` | 必填，无默认 | 院内 FHIR 服务 Bearer 令牌；401/403 时引擎点名此变量 |
| `CDR_IDENTIFIER_SYSTEM` | 必填，无默认 | 登记主索引在 `Patient.identifier` 上使用的 system 值，token 检索形如 `{system}\|{value}` |
| `REGISTRY_BASE_URL` | 必填，无默认 | 专病库登记接口基地址；写入路径为 `{REGISTRY_BASE_URL}/api/v1/registry-entries` |
| `REGISTRY_API_TOKEN` | 必填，无默认 | 专病库 Bearer 令牌 |
| `REGISTRY_PAYLOAD_FORM` | `field-level` | 推送体形态：`field-level` 字段级增量 / `whole-entry` 整条但只带变化字段；取值非法时报错并列出允许值 |
| `MODEL_BASE_URL` | 不配置即关闭模型 | OpenAI-compatible 模型网关地址；三项要么全配、要么全不配 |
| `MODEL_API_KEY` | 不配置即关闭模型 | 模型网关 api_key |
| `MODEL_NAME` | 不配置即关闭模型 | 模型名 |
| `MODEL_TIMEOUT_MS` | `20000` | 模型调用超时（毫秒） |
| `FHIR_MAX_CONCURRENCY` | `4` | 批量检索并发上限 |
| `MERGE_CONFIDENCE_THRESHOLD` | `0.80` | 归并置信度阈值；低于阈值标「需人工判定」且建议值留空 |
| `RUN_LOG_DIR` | `logs` | 本机结构化运行日志（JSONL）目录；每行一条记录检索的阶段、行标识、错误码、耗时与尝试次数 |
| `config/field-spec.json` | 项目自带 | 受控字段口径表：逐字段声明来源、参不参与比对、是不是派生、是不是受控编码；**表里没声明的列不参与比对** |

### CLI 子命令 / 接口端点

| 命令或路径 | 用途 | 关键参数 |
|------------|------|----------|
| `node dist/cli.js doctor` | 体检九个环境变量与配置合法性 | 无 |
| `node dist/cli.js sheet` | 读表 → 规范化行 → 打印行 JSON 与行级问题清单 | `--in` 登记表 CSV；`--mapping` 列映射配置；`--out` 结果文件；`--checklist` 待人工处理清单 CSV |
| `node dist/cli.js lookup` | 只读检索：按登记主索引查院内记录 → 逐行标「命中 / 歧义 / 零命中 / 未完成」 | `--in` 登记表 CSV；`--mapping` 列映射配置；`--out` 结果文件；`--log` 运行日志路径；`--checklist` 待人工处理清单 CSV |
| `node dist/cli.js caliber` | 口径自查：打印当前生效的字段口径清单、逐列判定与派生字段结果（离线，不连院内） | `--in` 登记表 CSV；`--spec` 字段口径表；`--replay` 离线回放集目录；`--limit` 派生结果只算前 n 位；`--out` 结果文件 |
| `node dist/cli.js align` | 读表 → 批量检索院内记录 → 逐字段比对 → 出结果表 | `--in` 输入契约 JSON / CSV；`--out` 结果文件 |
| `node dist/cli.js push` | 按确认闸门筛选 → 逐行推送专病库 | `--in` align 结果；`--out` 推送回执 |
| `node dist/cli.js summary` | 输出一致运行摘要 | `--in` align 结果；`--run-log` 本机 run-log |
| `GET {cdr_base_url}/fhir/R4/Patient?identifier={system}\|{value}` | 按登记主索引取院内患者 | `Authorization: Bearer $CDR_API_TOKEN`；`Accept: application/fhir+json` |
| `GET {cdr_base_url}/fhir/R4/Condition?subject=Patient/{id}` | 取院内诊断与分期 | 同上；分页按 Bundle `link[relation=next]` 取完 |
| `GET {cdr_base_url}/fhir/R4/Encounter?patient={id}` | 取院内就诊（派生首次入院日 / 本次就诊开始） | 同上 |
| `POST {registry_base_url}/api/v1/registry-entries` | 写出站登记条目 | `Authorization: Bearer $REGISTRY_API_TOKEN`；`Idempotency-Key: sha256(登记主索引\|字段路径\|旧值\|新值)` |

### 错误与降级

| 场景 | 表现 | 处理方式 |
|------|------|----------|
| 登记表缺必填列 | 读表即失败 | 点名缺哪一列（如「登记表缺少必填列：登记号」），该列补齐后重跑 |
| 表内编码非 UTF-8 | 自动探测 | UTF-8 / UTF-8+BOM / GBK 自动识别；两码混排按连续中文段逐段解码，识别不出时报行级错误 |
| 表头有空列名或重复列名 | 该列不参与比对 | 表级提示写明哪些列被跳过，其余列照常比对 |
| 某行脏数据（列数不符 / 缺登记号 / 登记号重复） | 该行被阻断 | 行级错误码 + 处置建议进问题清单；行本身保留，不静默丢弃，其余行照常处理 |
| 缺环境变量 | 启动即失败 | 逐个点名（如「缺少环境变量：CDR_BASE_URL、CDR_API_TOKEN」），不填假值、不静默降级 |
| 运行日志写不出去 | 本批结果照常给出 | 在结果的 `runLog.error` 里写明失败原因与路径，不假装记下了 |
| 院内 401 / 403 | 该批次终止 | 错误文案点名 `CDR_API_TOKEN` 或 `CDR_BASE_URL`，请信息科核对令牌与地址 |
| 院内 404 | 该行判零命中 | 标「零命中」，**不产出任何差异值**，不进推送体 |
| 院内超时 / 5xx / 429 | 读侧该行标「未完成」；写侧该行失败 | 读侧不自动重试，提示稍后重跑本批（检索失败 ≠ 零命中，两者分开计数）；写侧退避重试（≤3 次），超次置「待重试」进重试队列 |
| 院内 4xx（其余） | 该行失败 | 不重试，给行级错误码与处置建议 |
| 响应非 JSON / 缺关键字段 | 该行失败 | 显式行级错误码 + 原因，**不静默改值、不产出差异值** |
| 命中 > 1 | 该行判歧义 | 标「命中歧义」，**绝不取第一条**，不产出差异值 |
| 推送前院内值已被改 | 该行拒写 | 标「院内已变更，需重查」，同批其余行不受影响 |
| 模型不可达 / 超时 / 输出非法 | 归并与说明降级 | 建议值留空并标「需人工判定」；AI 说明列填固定模板句；**状态不被误推进** |
| 非法状态迁移（如「不采纳」→「已推送」） | 拒绝迁移 | 报「当前状态 → 目标状态」与允许目标列表 |
| 确认列取值不在白名单 | 该行不推进 | 行级错误码并列出允许取值（待确认 / 采纳 / 不采纳 / 无需确认） |
| 表里有列但口径表没声明 | 该列不参与比对 | 显式标「口径未声明」，不猜值、不产出差异值；补进口径表后重跑才参与比对 |
| 口径表本身有冲突 | 启动即失败 | 点名冲突字段（如「人工补充列『随访电话』不能参与比对」），不带着冲突开跑 |
| 清单落盘失败 | 本批结果照常给出 | 抛错点名目标路径，清除临时文件，不留半截清单 |

### 对接现有系统

| 方向 | 对端 | 形态 | 凭据来源 |
|------|------|------|----------|
| 出站读 | 院内 FHIR 服务（CDR） | `GET /fhir/R4/Patient\|Condition\|Encounter`，`Accept: application/fhir+json`，按 Bundle `link` 分页取完 | `CDR_BASE_URL` / `CDR_API_TOKEN` / `CDR_IDENTIFIER_SYSTEM` |
| 出站写 | 专病库登记接口 | `POST /api/v1/registry-entries`，body 为 FHIR R4 风格登记条目 JSON（`identifier` / `subject` / `changedFields` / `ifMatch` / `extensions`），登记专用列只走 `extensions` | `REGISTRY_BASE_URL` / `REGISTRY_API_TOKEN` |

- 凭据一律从环境变量读，代码里不出现真实地址与令牌；默认启动路径指向真实端点。
- 假 CDR / 假专病库只存在于 `tests/`，用于离线回放与协议兼容测试，**不是**最终对接方式。
- 写回方向本产品**只写专病库**，不写 HIS/EMR 主数据、不改写登记员的人工补充列。

## 典型场景

### 场景 1：登记员每周把上报到齐的表跑一次对齐

1. 在登记表里确认首行表头在位、登记号列没有空缺（空缺行会在结果里单独列为问题行）。
2. 点表头的「与院内数据对齐」按钮，宏把已用区域导出成契约格式的 `rows.json`。
3. 宏调用本机引擎，引擎逐行检索院内记录并把五列新结果回写到原表末尾。

```bash
node dist/cli.js align --in rows.json --out result.json
```

### 场景 2：登记员逐行确认差异后推送

1. 在「差异」列看到标红的字段，在「建议值」列看到建议写法（分期、方案类自由写法的归并建议）。
2. 把要采纳的行在「确认」列改成「采纳」；拿不准的留「待确认」，引擎会把它列进待人工处理清单。
3. 再跑一次推送，引擎只把「采纳」行的**变化字段**推给专病库，并把逐行回执写到表尾回执区。

```bash
node dist/cli.js push --in result.json --out push.json
```

### 场景 3：登记处负责人周会前看本周期进度

1. 打开结果表，表尾回执区第一行就是批次键、检索参数串、推送时刻与各类计数。
2. 待确认数不为零时，回执区列出了还悬着的行号；缺行区列出了院内有、本表没有的登记号。
3. 需要逐行追原因时，看引擎输出的行级问题清单（行号 + 错误码 + 处置建议）。

```bash
node dist/cli.js summary --in result.json
```

## 输出样例

### 待人工处理清单（CSV）

一行一条问题，登记员照着改表即可。清单里只有登记主索引占位标识，落盘前自动脱敏。

```csv
行号,登记号,错误码,问题,原因,处置建议,是否阻断推送
123,,MISSING_REGISTRY_ID,缺登记号,第 123 行缺少登记号,补齐登记号后重跑；缺登记号的行无法与院内记录绑定,是
124,REG-DUP-0001,DUPLICATE_REGISTRY_ID,登记号重复,登记号 REG-DUP-0001 在本表出现 2 次,同一登记号多行会与院内记录产生歧义，请合并或删除重复行后重跑,是
126,REG-9901,COLUMN_COUNT_MISMATCH,列数不符,第 126 行有 3 个单元格，表头是 5 列,该行列位可能已错位，本行不参与比对，请核对分列后重跑,是
3,REG-0002,AMBIGUOUS_MATCH,院内命中多条,登记号 REG-0002 在院内检索到 2 条患者记录,院内同一登记号对应多条记录，本行不产出差异值、不进推送体；请先在院内确认唯一记录后重跑,否
```

「是否阻断推送」分两档：**读表侧的脏行**（列数不符 / 缺登记号 / 登记号重复）会挡住这一行的比对与推送；**检索侧的判定**（院内命中多条 / 院内无此记录）不挡推送，只是这一行本轮拿不到院内值、不产出差异值。

## 架构与数据流

```
┌──────────────────┐   rows.json（契约）   ┌──────────────────────────────┐
│ 登记表 Excel/WPS │ ───────────────────► │ 引擎：读表 → 规范化 → 检索    │
│   或 CSV 文件    │                      │   GET /fhir/R4/Patient|...    │
└──────────────────┘                      └───────────────┬──────────────┘
        ▲                                             │ 逐行权威记录
        │                                             ▼
        │                                   ┌────────────────────────┐
        │                                   │ 差异引擎：最小操作集合  │
        │                                   │  add / replace / remove│
        │                                   └───────────┬────────────┘
        │                                               │ Operation[]
        │                                               ▼
        │              ┌──────────────────────────────────────────┐
        │              │ 归并层（受控词表 → 规范化 → 模型兜底）    │
        │              │ 模型不可达 → 建议值留空 + 需人工判定       │
        │              └───────────────────┬──────────────────────┘
        │                                  ▼
        │              ┌──────────────────────────────────────────┐
        │              │ 确认闸门：只有「采纳」行构造请求体         │
        │              └───────────────────┬──────────────────────┘
        │                                  ▼
        │                        POST /api/v1/registry-entries
        │                        Idempotency-Key: sha256(...)
        │                                  │
        │                                  ▼
        │      ┌───────────────────────────────────────────────────────┐
        └───── │ 结果表：原列 + 院内值/差异/建议值/确认/AI说明 +        │

               └───────────────────────────────────────────────────────┘
                                  │
```

### 关键不变量

- **幂等键**：推送幂等键 = `sha256(登记主索引|字段路径|旧值|新值)`，与时间戳、重试次数、批次号无关；同键重放不产生第二条登记条目。
- **未确认不外发**：确认状态不是「采纳」的行不构造请求体，不发出任何请求。
- **单行失败不中断同批**：一行检索失败或推送失败，其余行照常处理并各自出回执。
- **失败不静默改值**：任何失败都只产出错误码与状态标注，不改动登记值、不推进状态。
- **模型不推进状态**：模型输出只进「建议值」与「AI 说明」两列，绝不自动采纳、绝不自动推送。
- **人工补充列只读**：登记员自己填的列（随访电话、生活方式备注等）在写回层强制跳过，内容逐字节不变。

## 安全与合规边界

- 不输出诊断与治疗建议，不自动签名或代签；模型只产生建议，采纳由登记员在表内完成。
- 导出物、run-log 与截图不含患者可识别明报（登记号一律用占位标识）。
- 语气为「待核对 / 建议值 / 请确认」，不判违规、不下结论。
