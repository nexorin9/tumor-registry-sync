# 视觉目标卡 · 肿瘤登记增量同步（表内呈现）

> 本文件是**设计意图**，不是渲染结果。真实运行截图在 `docs/screenshots/`（由收尾任务采集）。
> 两者的差距在 README 的「概念 / 实测对照」一节里如实标注。

本产品没有网页、没有面板，登记员看到的一切都发生在**一张 Excel / WPS 表**里。
所以视觉目标不是画一个控制台，而是说清**这张表长什么样、哪一格最显眼、颜色怎么分**。

唯一真源：`src/sheet/present/tokens.ts`（色值、字号层级、列宽、间距栅格、状态映射）。
本文件里出现的每一个色值、字号、列宽都能在该文件里找到对应项。

---

## 一、三个状态画面

### 状态 A · 起始态（登记员刚打开这张表）

表格只有登记员自己填的原列，插件**还没动过**。这一态的设计要点是「让登记员一眼认出这是我的表」。

```
┌──────────┬────────┬──────────────┬────────────────┬──────────────────┐
│ 登记号   │ 分期   │ 治疗方案     │ 随访电话       │ 生活方式备注     │   ← 冻结首行 + 筛选
├──────────┼────────┼──────────────┼────────────────┼──────────────────┤
│ REG-0001 │ ⅢB     │ 术后辅助化疗 │ 138****0001    │ 吸烟史           │
│ REG-0002 │ IIIB   │ 新辅助化疗   │ 138****0002    │ 吸烟, 每日10支  │
│ REG-0003 │        │ 同步放化疗   │ 138****0003    │                  │
└──────────┴────────┴──────────────┴────────────────┴──────────────────┘
```

| 元素 | 目标 |
|------|------|
| 表头 | 字重 600、字号 14px、白底 `#FFFFFF`、底部 1px 分隔线 `#D5D8DD` |
| 人工补充列 | 随访电话、生活方式备注两列**浅灰底** `#F7F8FA` + 左侧 3px 色条 `#BFC5CC`，提示「人工补充列 · 只读不覆盖 · 不参与差异比对」 |
| 参与比对列 | 白底 `#FFFFFF`，正文色 `#1F2329` |
| 冻结 | 首行冻结，纵向滚动时表头常驻 |
| 筛选 | 表头带筛选下拉，登记员可先按自己关心的列筛 |

**这一态没有**：任何新列、任何底纹、任何表尾区块。表还是那张表。

### 状态 B · 首个可用瞬间（点一次「与院内数据对齐」之后）

新列追加在**原表末尾**（原列一个字节不动），差异格上底纹，「确认」列出现下拉，
表尾浮出回执区。登记员此刻要做的只有一件事：**看差异列、点确认列**。

│          │        │              │ (浅灰底)      │ (浅灰底)        │              │ (红/黄底)                  │          │ (下拉)   │                    │

| 元素 | 目标 |
|------|------|
| **差异列**（最显眼） | 唯一大面积上色的一列；红底 `#FBEAEA` + 红字 `#A92020`（有差异）/ 黄底 `#FDF3DC` + 棕字 `#8A5B00`（待确认）/ 蓝灰底 `#EDF2F7`（零命中）。**一致的行不上底纹** |
| **确认列** | 下拉白名单：待确认 / 采纳 / 不采纳 / 无需确认。当前值「待确认」用黄底 `#FDF3DC` |
| **建议值列** | 可直接采纳的建议值；不可归并时**留空**并在状态列标「需人工判定」，不猜 |
| **AI 说明列** | 只放一句话解释与降级模板句，不放结论；模型不可达时填「字段口径不一致，请人工核对（模型未启用）」 |
| **表尾回执区** | 标题行蓝底 `#E8F1FD`（16px/600）+ 计数行浅灰底 `#F7F8FA`（12px）+ 明细行白底/隔行 `#FAFBFC` |
| **表尾缺行区** | 标题行黄底 `#FDF3DC`（16px/600），计数行写「不自动入表」，明细行逐条一条 |
| **人工补充列** | 仍是浅灰底 `#F7F8FA`，**内容逐字节不变** —— 插件不碰这两列 |

### 状态 C · 成形态（确认完、推完一轮之后）

表里留下的是「这一批到底推了什么、还欠着什么」：确认列落成终态，回执区变成逐行证据，
缺行区把该补的登记号点名。

| 元素 | 目标 |
|------|------|
| 已推送行 | 确认列绿底 `#E8F5EC` + 绿字 `#246B39`；差异列降级为灰底 `#F2F3F5`，说明「这批已经处理完了」 |
| 不采纳行 | 灰底 `#F2F3F5`，与「已推送」区分靠**文字**而不是颜色 |
| 命中歧义 / 零命中 | 浅橙 `#FCEEE5` / 蓝灰 `#EDF2F7`，两个都是「要人工看一眼」 |
| 回执区明细 | 幂等键与批次键用等宽字体（`SF Mono` / `Consolas`）+ `tabular-nums`，上下行能对齐 |
| 缺行区 | 始终留在表尾，**不进正文**；确认列初始「待确认」，不自动入表 |

## 三、字体层级

| 层级 | 字号 | 字重 | 行高 | 用在哪 |
|------|------|------|------|--------|
| 区块标题 | 16px | 600 | 24px | 表尾两个区块的标题行 |
| 列名 | 14px | 600 | 20px | 表头列名 |
| 正文 | 14px | 400 | 20px | 单元格正文 |
| 辅助说明 | 12px | 400 | 18px | 计数行、提示语 |
| 徽标 | 12px | 500 | 18px | 状态徽标文字 |
| 指标数字 | 20px | 600 | 28px | 表尾计数数字 |

- 中文系统栈：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", "Source Han Sans SC", sans-serif`
- 数字与键值一律等宽 + `tabular-nums`：`"SF Mono", "JetBrains Mono", Consolas, "Courier New", monospace`
  （登记号、计数、幂等键、批次键要能上下对齐看）
- 间距守 8px 栅格：4 / 8 / 12 / 16 / 24 / 32 / 40

## 四、信息层级（登记员扫一眼的顺序）

1. **差异列** —— 唯一大面积上色的一列，决定「这一批有没有活要干」；
2. **确认列** —— 唯一要动手的列（下拉四值），决定了「我下一步做什么」；
3. **状态色** —— 差异列的底色直接给出严重度，不靠读文字；
4. **表尾回执区** —— 回答「上批推了什么、还欠几行、批次键是多少」；
5. **表尾缺行区** —— 回答「院内有、这张表没有的登记号是哪些」；
6. **AI 说明列** —— 最后看；只解释，不下结论。

人工补充列刻意放在低对比位置（浅灰底、辅助文字色），**不参与差异比对**，
登记员不会误以为插件要动它。

## 五、必须可达的约束（不许画做不到的效果）

本产品的渲染载体只有 Excel / WPS 的**单元格格式**。因此：

| 能做（已规划） | 不能做（禁止出现在本卡与实现里） |
|----------------|----------------------------------|
| 单元格纯色填充（`Interior.Color`） | 渐变填充、阴影、圆角单元格 |
| 字体色 / 字号 / 字重 / 等宽 | 引入图标库、emoji 图标 |
| 列宽、行高、自动换行 | 悬浮动效、动画、卡片阴影 |
| 冻结首行、自动筛选 | 自定义 Web 字体（表格端不保证有） |
| 确认列数据验证下拉 | 单元格内嵌图表、表单控件 |
| 斑马纹（隔行上色） | 表格内嵌网页、iframe |
| 表尾区块（多行拼接） | 弹窗、toast（宏侧用 MsgBox 反馈） |

色值到 Excel 填充色的换算由 `excelFillArgb()`（**BGR** 顺序）承担，
宏里直接 `Range.Interior.Color = excelFillArgb(...)` 的结果，避免红底画成蓝底。
